# 오늘의 기록 — 시간대별 그룹핑(성능 개선) 계획

> 다음 세션에서 이 파일을 읽고 이어서 작업할 것. 진행 상태는 하단 [진행 상태] 참고.

## 배경/문제 (2026-08-20 기준)

- "오늘의 기록" 패널(`CameraView.tsx`의 `showLog` 블록)은 당일 전체 레코드를 필터/페이지 없이
  `.map()`으로 한 번에 렌더링한다.
- 각 항목은 저장된 원본 해상도 스냅샷을 그대로 `<img className="log-thumb">`로 렌더링한다.
  CSS로 56×56 크기로만 줄여 보여줄 뿐, 브라우저는 원본 해상도 그대로 디코딩한다.
- 저장 빈도 자체는 이미 완화됨 — `handleDetectionResult`에 `DETECTION_SAVE_COOLDOWN_MS`(10초)
  쿨다운을 추가해서, 같은 위반이 계속 화면에 잡혀 있어도 10초에 1건만 저장한다(커밋 `c33780c`).
  다만 활동이 많은 날엔 여전히 하루 수백~수천 건까지 쌓일 수 있다.
- 결과: 기록이 많이 쌓인 날엔 리스트 스크롤 버벅임, 심하면 메모리 부족으로 브라우저 탭이
  죽을 위험이 있다.
- 전체화면 앨범 뷰어(확대 + 좌우 스와이프/버튼/키보드 넘기기)는 이미 구현·커밋됨
  (커밋 `57181f6`). 이건 "연 뒤"의 문제이고, 이번 건은 "기록이 많을 때 목록 자체가
  무거워지는" 문제다.

## 해결 방향: 시간대(1시간 단위) 아코디언 그룹핑

- `capturedAt` 기준으로 레코드를 시간대별로 묶는다 (예: "오후 3시" 그룹).
- 그룹 헤더는 항상 보이되(건수 + 고위험 이벤트 요약 배지), **펼쳐진 그룹의 레코드(이미지
  포함)만 실제로 DOM에 렌더링**한다. 접힌 그룹은 이미지를 아예 렌더링하지 않는다.
- 이렇게 하면 동시에 화면에 존재하는 이미지 수가 "하루 전체"가 아니라 "펼쳐진 시간대 하나치"
  수준으로 줄어들어 성능 문제가 해결된다.
- 부가 효과: 헤더 요약만 봐도 하루 흐름 파악 가능 — 사진을 하나도 안 열어봐도
  "오후 3시대에 고위험 2건" 같은 걸 바로 확인할 수 있다. 지금처럼 스크롤하며 일일이
  찾을 필요가 없어진다.

## 결정 사항 (2026-08-20 확정)

1. **아코디언 방식**: 한 번에 하나의 시간대만 펼침. (확정)
2. **기본 상태**: "오늘의 기록" 패널을 열 때마다 가장 최근 시간대를 자동으로 펼침. (확정)

## 구현 스케치

- 대상 파일: `web/src/components/CameraView.tsx`("오늘의 기록" 렌더링 부분,
  `showLog` && `.log-drawer-list`), 필요 시 `web/src/styles/globals.css`.
- `todayRecords`를 `capturedAt`의 시(hour) 기준으로 그룹핑하는 헬퍼 함수 추가.
  예: `groupRecordsByHour(records: DetectionRecord[]): { hourLabel: string; records: DetectionRecord[] }[]`
- 펼쳐진 시간대를 추적하는 state 추가 (단일 아코디언이면 `expandedHour: string | null`).
- 그룹 헤더 클릭 시 펼침/접힘 토글. **접힌 그룹은 레코드 `.map()` 자체를 호출하지 않도록**
  조건부 렌더링 (이게 핵심 — 접힌 그룹의 이미지가 DOM에 존재하지 않아야 성능 효과가 있음).
- 헤더 요약: 건수 + `HIGH_PRIORITY_LABELS`(fire_smoke, man_down)에 해당하는 건수.
- **라이트박스(앨범 뷰어) 연동 주의**: 현재 라이트박스는 `todayRecords` 전체 배열의 인덱스
  기준으로 이전/다음 이동한다(`lightboxIndex`, `showPrevRecord`/`showNextRecord`).
  그룹핑을 적용해도 이 전체-배열 기준 이동은 그대로 유지할 것 — 그룹 접기/펼치기는 "목록
  화면"에서만 적용되는 표시 방식이고, 라이트박스로 확대해서 넘겨보는 동작은 지금처럼 그룹
  경계와 무관하게 전체 기록을 순서대로 넘길 수 있어야 한다.
